

# MiniBLC

MiniBLC 是一个使用 Python 实现的最小化区块链项目，旨在通过实现区块创建、哈希计算、区块链接和完整性验证等基础功能，帮助开发者理解区块链的核心工作原理。

本项目定位为区块链入门实践项目，重点关注基本数据结构、哈希算法、链式存储、完整性验证以及 Git 版本管理等工程实践。

## 1. 项目简介

区块链是一种由多个区块按照一定规则连接形成的数据结构。每个区块保存自身的数据、时间戳、前一区块的哈希值等信息，通过哈希引用建立区块之间的关联。

MiniBLC 尝试以尽可能精简的代码实现区块链的基础流程，包括：

- 创建创世区块，初始化区块链。
- 根据已有区块创建新区块。
- 使用 SHA-256 计算区块哈希。
- 根据区块高度查询区块信息。
- 遍历并查看区块链中的区块。
- 检查区块数据完整性及区块之间的链接关系。
- 通过测试程序模拟区块哈希篡改和区块链接断裂。

通过本项目，开发者可以了解区块链的基本数据结构及完整性校验机制，并在此基础上继续扩展功能。

## 5. 功能说明

### 5.1 创世区块初始化

创建 `Blockchain` 对象时，程序会自动创建创世区块，并将其作为区块链的第一个区块。

创世区块的高度为 `0`，前置哈希为字符串 `"0"`。

### 5.2 添加新区块

调用 `add_block_to_chain(data)` 添加新区块。

程序会获取当前链尾区块，将其哈希作为新区块的 `prev_hash`，并将高度设置为前一区块高度加一。

随后，新区块会被追加到区块链中。

### 5.3 查询区块

项目支持查询区块链中的区块数量、当前区块高度，以及根据区块高度查询具体区块。

查询结果可以展示区块的数据、时间戳、前置哈希和当前哈希等信息。

### 5.4 查看区块链

程序可以遍历区块链中的所有区块，并输出各区块的基本字段，方便观察区块之间的连接关系。

### 5.5 区块链完整性验证

`validate_chain()` 用于检查区块链的基本完整性，主要包括：

- 检查创世区块的基本字段和哈希。
- 检查各区块的哈希是否与当前区块字段匹配。
- 检查当前区块的 `prev_hash` 是否等于前一区块的 `hash`。

如果发现异常，程序返回 `False`；如果检查通过，则返回 `True`。

## 6. 核心原理

### 6.1 区块的数据结构

每个区块包含以下基本字段：

| 字段          | 含义                        |
| ----------- | ------------------------- |
| `data`      | 区块保存的数据                   |
| `timestamp` | 区块创建时的 Unix 时间戳，以秒为单位     |
| `prev_hash` | 前一个区块的哈希值                 |
| `hash`      | 根据当前区块数据、时间戳和前置哈希计算得到的哈希值 |
| `height`    | 区块在链中的高度，创世区块高度为 `0`      |

### 6.2 哈希计算

项目使用 SHA-256 计算区块哈希。

当前实现将区块数据、时间戳和前置哈希按照固定顺序拼接，并使用 `|` 作为分隔符：

```python
digests = self.data + "|" + str(self.timestamp) + "|" + self.prev_hash
```

随后，将拼接后的字符串编码为字节，再计算 SHA-256：

```python
sha256_hash = hashlib.sha256()
sha256_hash.update(digests.encode())
block_hash = sha256_hash.hexdigest()
```

因此，当前区块哈希的计算规则可以表示为：

```
hash = SHA256(data + "|" + timestamp + "|" + prev_hash)
```

注意：`height` 不参与当前版本的哈希计算。

如果 `data`、`timestamp` 或 `prev_hash` 发生变化，重新计算得到的哈希通常会与原哈希不同。

### 6.3 区块链接

区块通过 `prev_hash` 与前一区块建立关联。

例如：

```
Genesis Block
height = 0
hash = H0
     |
     v
Block 1
height = 1
prev_hash = H0
hash = H1
     |
     v
Block 2
height = 2
prev_hash = H1
hash = H2
```

其中，每个新区块保存前一区块的哈希值，形成连续的链式结构。

如果某个区块的前置哈希与实际前一区块的哈希不一致，区块之间的连接关系就会被破坏。

### 6.4 完整性验证

完整性验证主要分为两类。

第一类：区块自身的哈希验证。

重新计算区块哈希，并与保存的 `hash` 比较。如果两者不一致，说明区块当前字段与其保存的哈希不匹配。

第二类：区块之间的链接验证。

检查当前区块的 `prev_hash` 是否等于前一区块的 `hash`。如果不相等，则说明区块之间的链接关系存在异常。

需要注意，哈希验证并不等于绝对防篡改。如果攻击者修改区块内容后，重新计算该区块及后续区块的哈希，基础校验仍可能通过。因此，本项目实现的是基础完整性检查，并未实现分布式共识、数字签名或其他完整的防篡改机制。

## 7. 测试说明

项目使用 Python 标准库 `unittest` 对区块链的基础篡改检测进行测试。

### 7.1 哈希篡改测试

测试步骤：

1. 初始化区块链并添加测试区块。
2. 直接修改某个区块保存的 `hash`。
3. 不重新计算该区块的哈希。
4. 调用 `validate_chain()`。

预期结果：程序检测到区块哈希不匹配，并返回 `False`。

### 7.2 区块链接断裂测试

测试步骤：

1. 初始化区块链并添加测试区块。
2. 修改某个区块的 `prev_hash`，使其不再指向实际前一区块。
3. 重新计算当前区块的 `hash`，使当前区块自身的哈希校验通过。
4. 调用 `validate_chain()`。

预期结果：程序检测到区块前后连接关系不一致，并返回 `False`。
